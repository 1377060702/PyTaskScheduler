# PyTask 调度器 —— Windows Python 脚本定时任务程序

纯 Python 标准库实现（tkinter GUI + 后台调度线程），**零第三方运行依赖**。支持 Windows 10 / 11；脚本方式需同时保留 `PyTaskScheduler.py` 和 `windows_process.py`，打包的主程序为单个 EXE。运行任务脚本仍需配置 Python。

## 启动方式

| 方式 | 操作 |
|---|---|
| 双击（推荐） | `PyTaskScheduler.exe`，无需任何 Python 环境 |
| 命令行 | `pythonw PyTaskScheduler.py`（无控制台）或 `python PyTaskScheduler.py` |

exe 与脚本模式程序自动适配：配置、日志、锁文件始终创建在**程序所在目录**。

## 首次使用（两步）

1. **启动后先点右上角「设置」**：
   - **Python 目录（必填）**：填 Python 安装目录（如 `D:\Python`）或 python.exe 完整路径。**不配置任务无法运行**，每次触发会记一条「错误：未配置 Python 目录」。
   - 错过处理：周期任务迟到不超过 5 分钟仍可执行；超过 5 分钟时，补跑一次 / 直接跳过（默认补跑一次）。有限重复窗口已结束时不补跑，详见下文。
   - 记录保留天数：`runs-YYYY-MM-DD.jsonl` 等日志自动清理，0 = 永久保留。
2. **新建任务**：工具栏「新增任务」，填写脚本、触发器、运行方式后保存。

## 任务字段说明

| 字段 | 说明 |
|---|---|
| 脚本路径 | Python 脚本**完整路径**（「浏览…」选择即自动填入，并记住上次选择目录） |
| 运行参数 | 传给脚本的命令行参数，如 `--interval 30 -v` |
| 工作目录 | 脚本的 cwd，空 = 默认 |
| 窗口方式 | **无窗口（纯后台，无 CMD 弹窗）**：输出重定向到 `logs\run_任务ID_日期.log`（同任务同天合并追加，每次运行前有 `===== [时间] 开始运行 =====` 分隔行）；**弹出 CMD 窗口**：新开控制台，可实时看输出 |
| 触发类型 | **单次**（指定日期时间，精确到**秒**）／ **每天·每隔 N 天**（每个触发日到点启动，可选窗口内重复）／ **每隔一段时间重复**（从固定起点连续重复，可设持续时长，0 = 无限期） |
| 超时限制 | 运行超过 N 秒立即用 `taskkill /F /T` 结束**整个进程树**；0 = 不限制 |
| 冲突策略 | 上一次没跑完：**跳过本次**（不开新一次）或 **终止上一次并立即运行新一次** |

## 每天 / 每隔 N 天与重复窗口

在「每天 / 每隔 N 天」中设置开始时间、每隔天数和起始日期；起始日期留空会在保存时固定为当天。勾选「重复任务，每」后，填写重复间隔和持续时间，单位可选秒、分钟、小时。

| 设置示例 | 计划触发时间 |
|---|---|
| 每天 09:00，不勾选重复 | 每天仅在 09:00 触发一次 |
| 每天 09:00，每 5 分钟重复，持续 2 小时 | 09:00、09:05…11:00，共 25 个计划格；11:00 包含在内 |
| 每天 23:00，每 30 分钟重复，持续 2 小时 | 23:00、23:30、次日 00:00、00:30、01:00；下一轮仍从当天 23:00 开始 |
| 起始日 2026-09-23，每隔 3 天，09:00 起每 5 分钟重复 2 小时 | 9 月 23 日、26 日、29 日各自开启一轮窗口 |

- 每隔天数、启用后的重复间隔和持续时间必须为正整数；持续时间不得小于重复间隔，也不得超过 N 天。日期、时间、数字或单位无效时不保存，不静默替换成默认值。
- 持续时间允许跨午夜。截止时刻恰好落在重复网格上时包含该次触发；两轮窗口在同一时刻相接时，只触发一次。
- 窗口结束后不强行终止已运行的任务；运行时长仍由「超时限制」控制。计划格数量不等于实际成功运行次数，冲突、停用和错过策略都可能跳过执行。
- 未勾选重复时仍是每个触发日一次；旧配置没有重复字段时保持原行为，不会变成新的任务类型。旧任务空起始日期会优先沿用已有下次/上次运行日期，否则固定为当天。
- 编辑任务不清空运行记录；修改调度字段才重算下次运行时间。保存后的配置变更会取消旧配置尚未启动的执行快照。

## 任务管理便利功能

- **搜索框**：工具栏右侧输入即过滤（匹配任务名 / 脚本路径 / 分组，忽略大小写），几百个任务秒定位
- **分组交互**：点击分组行**任意位置**展开/折叠；右键分组行 →「新增任务（分组：X）」自动预选该分组
- **右键任务菜单**：立即运行 / 启停 / 编辑 / **复制任务**（一键建同规格任务，弹编辑框微调）/ 查看运行记录 / **打开运行输出（今日）** / 导出XML / 删除
- 点击空白处取消选中；双击任务行 = 编辑；所有弹窗居中于主窗口
- **状态栏**实时显示任务数、运行中数、**今日成功/失败/跳过计数**（有失败整条红字；跳过的任务行显示琥珀色——高频任务"半跑半跳"一眼可见）
- 列表增删改后自动保留选中与滚动位置，批量整理不丢上下文

## 开机自启 / 挂掉自动拉起

在「设置」对话框底部有两个开关（保存后生效）：

| 开关 | 原理 |
|---|---|
| **开机自动启动调度器** | 写当前用户注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（值名 PyTaskScheduler，命令为 pythonw.exe + 主程序路径）。用 `任务管理器 → 启动应用` 或注册表可直接核查。修改 Python 目录后保存设置会自动同步注册表里的路径 |
| **程序挂掉后自动拉起** | 注册 Windows 计划任务 `PyTaskSchedulerWatchdog`（每 2 分钟运行一次 `watchdog.py`，无窗口）。看门狗用**文件锁**检测调度器存活：调度器启动时持有 `scheduler.lock` 的锁，进程崩溃 / 被结束时操作系统自动释放锁 → 看门狗发现锁空闲就用 pythonw 重新拉起调度器；活着则静默退出，**绝不重复启动** |

配套机制：

- **单实例保护**：主程序启动时先抢 `scheduler.lock` 文件锁，抢不到说明已在运行，弹窗退出——既防止双开重复触发任务，也是看门狗的存活依据。
- 两个开关互不依赖，可只开其中之一；都需要先配置好 Python 目录（否则保存时会提示未生效原因）。
- 看门狗计划任务默认"已在运行则不启动新实例"，即使调度周期重叠也不会跑出多个看门狗。
- 「开机自动启动」实际在当前用户登录后启动；看门狗本身仍依赖 Windows 任务计划程序，不提供无人登录的系统服务执行能力。

## 高频任务（每秒一跑）使用建议

调度核心的高频行为：

- **触发时间**：调度循环自适应等待，临近触发点时收窄等待；`next_run` 按固定时间网格推进，避免按任务结束时间累加造成漂移。实际启动延迟受系统负载、写盘、线程调度和进程启动影响，不保证 ±10ms 或实时执行
- **后台启动**：进程启动由工作线程执行；计划落盘和进程创建的关键步骤使用锁保证一致性，磁盘慢或系统负载高时可能延迟其他触发
- **先保存再启动**：每次消费到期计划格时，先将下次运行时间通过临时文件、`fsync` 和原子替换保存；失败则保留原计划并暂不启动。其他状态更新仍合并保存，高频任务需考虑每次触发的写盘开销
- **日志按天滚动**：`logs\runs-YYYY-MM-DD.jsonl`，按保留天数整文件删除（默认 7 天，0=永久），**跨天自动执行清理，常驻运行无需重启**，不会无限膨胀、不会全文件重写

使用建议：

1. 1 秒级任务务必选**无窗口（纯后台）**模式——弹 CMD 模式每秒弹窗无法使用
2. 脚本本体执行时长需明显小于触发间隔（1 秒任务建议脚本 < 0.5 秒），否则按冲突策略处理：跳过 / 终止上一次
3. 每次运行都是独立的 python.exe 进程（含解释器冷启动 ~50ms），这是"定时跑脚本"模型的固有开销
4. **磁盘量估算**：每条记录约 300 字节 → 单个 1 秒任务 ≈ 25MB/天；10 个 ≈ 250MB/天。默认保留 7 天，请按量调整（设置 → 记录保留天数）
5. 界面刷新 600ms 一次，任务列表几百个也流畅

## 运行记录

- **`logs\runs-YYYY-MM-DD.jsonl`**（按天滚动）：记录已执行及运行阶段跳过的任务，含计划触发时间、开始、结束、耗时（秒）、退出码、状态（成功/失败/超时结束/被终止/跳过/错误）、是否补跑、备注。GUI「运行记录」窗口按筛选条件显示最新 5000 条；因错过策略直接消费而未启动的旧计划格不保证逐格生成记录。
- **按天日志 `logs\daily\YYYY-MM-DD.log`**（每行文本）：
  ```
  [2026-09-17 09:30:05] [成功] 任务「每日备份」 backup.py 耗时 3.2 秒 退出码:0
  [2026-09-17 09:35:01] [失败] 任务「数据抓取」 fetch.py 耗时 12.7 秒 退出码:1 退出码 1
  [2026-09-17 09:36:00] [超时结束] 任务「心跳检测」 ping.py 耗时 30.0 秒 退出码:- 运行超过 30 秒，已强制结束
  ```
  每天一个文件，记录**执行时间、脚本名、成功还是失败**，可直接用记事本 / Excel 打开。
- **单次运行输出**：无窗口模式的 stdout/stderr 存 `logs\run_任务ID_YYYYMMDD.log`（同任务同天一个文件、追加写，高频任务不会产生海量小文件；按保留天数自动清理，排查脚本问题用）。
- 「运行记录」窗口里的「清空记录」会同时清空全部 runs-*.jsonl 运行记录和按天日志（有确认提示）。
- 运行记录窗口还支持：任务 / 结果 / **时间**（今天、近 24 小时、近 1 小时）三维筛选，**先筛选再取最新 5000 条**，结果按记录时间从新到旧显示，不会误取文件前 5000 条；**双击任意记录直接打开该次运行的输出日志**；「自动刷新」开关（每 3 秒）。

## 任务导入 / 导出（Windows 任务计划程序 XML 格式）

### 导入
工具栏「导入XML」→ 选择任务计划程序导出的 `.xml`（支持 UTF-16 / UTF-8 编码）。映射规则：

| 任务计划程序 XML | 导入结果 |
|---|---|
| `TimeTrigger`（无重复） | 单次任务 |
| `CalendarTrigger` + `ScheduleByDay/DaysInterval` | 每天 / 每隔 N 天 |
| 上述 `CalendarTrigger` 再带 `Repetition/Interval/Duration` | 每天 / 每隔 N 天，在每个触发日的窗口内重复，保留起始日和 N 天周期 |
| `TimeTrigger` + `Repetition/Interval[/Duration]` | 从 StartBoundary 起连续间隔重复；Duration 省略时无限期 |
| `Settings/ExecutionTimeLimit`（PT1H 等） | 超时限制（秒）；省略按 Windows 缺省 72 小时，显式 PT0S 为不限制 |
| `MultipleInstancesPolicy=StopExisting` / `IgnoreNew` | 分别为终止上一次 / 跳过本次；Parallel、Queue 及未知值拒绝导入 |
| `Settings/Enabled=false` 或触发器 `Enabled=false` | 任务停用 |
| 周 / 月 / 登录 / 开机 / 事件触发器 | 拒绝导入，不转换为每天 |
| `Command` 为 python.exe | 脚本从 Arguments 中的 `.py` 参数提取；若当前未配置 Python 目录会**自动回填** |
| `Command` 为其他 exe | 拒绝导入（本程序只跑 Python 脚本） |

导入只接受一个支持的触发器和一个 Python Exec 动作；任务自动放入「导入」分组。带时区或小数秒的 StartBoundary、EndBoundary、非零随机延迟、窗口末端强制终止（StopAtDurationEnd=true）、无期限的每天重复窗口及其他不能表示的触发参数会明确拒绝。

XML 重复间隔须为 1 分钟至 31 天，每隔天数须为 1 至 365；持续时间至少 1 分钟且不短于间隔，每天重复窗口还须不超过 N 天。日期、时长和数字格式错误不会被忽略。Windows 的账户权限、电源、空闲、网络等条件不由本程序实现，导入不是对所有 Windows 设置的完整复制。

### 导出
右键任务「导出XML…」（或选中后点工具栏「导出XML」）→ 保存 `.xml`（UTF-8 BOM）。每天重复使用 `CalendarTrigger + ScheduleByDay + Repetition`，连续重复使用 `TimeTrigger + Repetition`；触发器、超时和多实例策略按上述范围对应，`StopAtDurationEnd=false`。Command 为当前配置的 python.exe 全路径，Arguments 为脚本 + 参数。

导出前检查 Windows XML 限制；例如本程序的每 1 秒任务不能导出成 Windows 每 1 秒重复，会明确报错并保留原输出文件。导出文件需在目标机器核对 Python 路径、工作目录和运行账户后导入。XML 元素顺序和字段范围以 [Microsoft Task Scheduler Schema](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-schema) 为依据。

## 调度精度与稳定性

- 调度线程自适应轮询：平时约 200ms 一轮，临近触发点收窄等待，按绝对时间网格推进；不提供实时性或固定毫秒误差保证。
- 配置写入采用「临时文件 + fsync + 原子替换」，减少部分写入风险；无法保证所有硬件、文件系统或断电场景下绝不丢数据。结构损坏时备份为 `config.json.bad` 并从空配置启动。
- 周期任务迟到 **≤5 分钟**，仍在有效窗口内时允许执行一次；迟到 **>5 分钟** 才按设置补跑一次或直接跳过。处理后直接对齐未来计划，不逐格追赶。
- 有限重复窗口过期后不补跑，不受「补跑一次」设置覆盖。截止整格仅保留 1 秒正常轮询容忍；例如 11:00 整格在 11:00:00.2 仍可启动，超过 11:00:01 不再启动。
- 单次任务错过超过 5 分钟不再补跑，标记「已完成」。
- 超时/冲突的强制结束**带死亡确认**：杀不掉时不开新实例（绝不同任务双开）、不误报「超时结束」。
- 任务参数按 Windows 规则拆分，路径中的反斜杠不会被转义吞掉。
- 关闭调度器时若有任务在运行，可选择终止它们、让子进程继续跑（调度器退出期间失去超时控制）或取消退出。取消退出会恢复调度；终止失败、暂停看门狗失败或配置保存失败时保留程序及任务管理关系。
- 看门狗启用时退出会再询问：**退出并暂停看门狗拉起**（下次启动程序时恢复）或仅退出（通常在下一次约 2 分钟的检查时拉起）。
- 对已持久化的运行进程，重启后按 PID 和进程创建时间核对身份，防止 PID 复用误认；可恢复管理的子进程继续遵循原超时起点，不能因重启获得新的完整超时时长。
- 崩溃恢复不保证 exactly-once：消费计划写盘后、子进程启动前崩溃，可能少执行一次；`Popen` 成功后、运行进程信息写盘前崩溃，仍有无法完整恢复的窗口。重要脚本应自行处理幂等和业务去重。

## 运行边界

- 本程序是当前用户会话中的桌面应用，必须保持运行；关机、睡眠和注销期间不能执行脚本。
- 不提供 Windows 服务或无人登录运行能力，不负责唤醒机器，也不实现电源、空闲、网络条件控制。
- 不支持多动作任务、多个触发器组合、周/月/事件触发器及完整的 Windows 账户权限模型；不能视为 Windows 任务计划程序的完整替代。
- 看门狗自动拉起仍由 Windows 任务计划程序执行；它不能消除系统休眠、用户会话和系统任务本身的限制。

## 封装成 EXE

exe 的 GUI 本身无需目标机器装 Python；跑任务脚本时仍需在设置里配置 Python 目录。已有 exe 不会自动包含源码修改，使用修改后的代码需重新打包并核对产物（需已安装 PyInstaller）：

```
python -m PyInstaller --onefile --noconsole --name PyTaskScheduler PyTaskScheduler.py
python -m PyInstaller --onefile --noconsole --name watchdog watchdog.py
```

**两个 exe 必须放在同一目录**使用；程序已自动适配 exe 模式：

- 配置 / 日志 / 锁文件都创建在 **exe 所在目录**（不受 PyInstaller 临时解压目录影响）
- 「开机自启」直接注册 `PyTaskScheduler.exe` 路径；「看门狗」计划任务直接运行 `watchdog.exe`，不再依赖 pythonw
- 双击 `PyTaskScheduler.exe` 即启动；打包时须先退出正在运行的实例（exe 被占用会打包失败）

注意：onefile 模式首次启动需解压到临时目录，比脚本模式慢 1~2 秒属正常；杀毒软件个别情况会误报 PyInstaller 打包文件，加白名单即可。

## 常见问题

- **提示「未配置 Python 目录」**：设置里填 Python 目录（目录或 python.exe 全路径均可），保存即可。
- **脚本路径想迁移机器**：任务里用脚本完整路径，换机器时迁移整个脚本目录并保持盘符路径一致，或逐任务改路径。
- **无窗口任务看不到输出**：去 `logs\run_任务ID_日期.log` 看输出（同任务同天合并在一个文件里，按「开始运行」分隔行区分每次）；或把任务改成「弹出 CMD 窗口」。
- **删除正在运行的任务**：会提示，确认后终止进程树并确认结束再删除；终止失败会保留任务并停用后续调度。
- **调度器已在运行但看不到窗口**：调度器可能被最小化 / 在其他虚拟桌面；再次双击启动器会因单实例锁弹窗提示。开着看门狗的话不必担心重启——直接任务管理器结束进程，2 分钟内会被自动拉起。
- **卸载自启**：设置里取消两个勾选并保存即可（自动清注册表与计划任务）。
